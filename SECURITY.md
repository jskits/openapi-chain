# Security

Report suspected vulnerabilities through [GitHub private vulnerability reporting](https://github.com/jskits/openapi-chain/security/advisories/new).
Include the package version, affected entry point, a minimal synthetic OpenAPI
example, expected/actual behavior, and whether the issue occurs with native Fetch.
Do not include production credentials, tokens, customer data, or private schemas.

The reporting form requires GitHub authentication and repository-side private
reporting to be enabled. If GitHub reports it unavailable, open an issue titled
“Private security reporting channel requested” with no vulnerability details so a
maintainer can arrange a private channel. Do not publish an exploit or sensitive
reproduction in the issue.

Maintainers should enable **Settings → Code security → Private vulnerability
reporting** before the first public release. This file documents the process; it
does not configure that GitHub setting or promise a response-time SLA.
